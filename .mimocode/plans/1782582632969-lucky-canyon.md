# Auction-Server Build Plan

## Overview
Complete backend implementation for CricAuction platform to support the existing frontend. Build full Node.js + Express + MongoDB + Socket.IO backend with all required APIs and real-time auction functionality.

## Target Structure
```
Auction-Server/
├── src/
│   ├── config/
│   │   └── db.js                      ← MongoDB connection setup
│   │
│   ├── models/                        ← Mongoose schemas
│   │   ├── User.js                    ← Organizer account
│   │   ├── Tournament.js              ← Tournament entity
│   │   ├── Player.js                  ← Registered player
│   │   ├── Team.js                    ← Franchise/team with budget
│   │   └── Bid.js                     ← Bid transaction record
│   │
│   ├── routes/                        ← Express route definitions
│   │   ├── auth.routes.js             ← POST /auth/login, /auth/register
│   │   ├── tournament.routes.js       ← CRUD /tournaments
│   │   ├── player.routes.js           ← CRUD /players
│   │   ├── team.routes.js             ← GET /teams, /teams/:id
│   │   └── auction.routes.js          ← Auction state endpoints
│   │
│   ├── controllers/                   ← Route handler logic
│   │   ├── auth.controller.js
│   │   ├── tournament.controller.js
│   │   ├── player.controller.js
│   │   ├── team.controller.js
│   │   └── auction.controller.js
│   │
│   ├── middleware/
│   │   ├── auth.middleware.js         ← JWT verification guard
│   │   └── errorHandler.js            ← Centralized error response formatter
│   │
│   ├── socket/
│   │   ├── auctionSocket.js           ← Socket.IO event handlers for live bidding

├── .env.example

```

## Implementation Steps

### Phase 1: Project Setup & Core Infrastructure
1. Create Auction-Server directory structure
2. Initialize package.json with dependencies (express, mongoose, socket.io, jsonwebtoken, cors, dotenv)
3. Set up environment configuration (.env.example)
4. Create MongoDB connection setup
5. Set up basic Express server with middleware

### Phase 2: Database Models & Schema
1. User model (organizer accounts)
2. Tournament model (tournament structure)
3. Player model (registered players)
4. Team model (franchises with budget)
5. Bid model (auction transactions)

### Phase 3: Authentication System
1. JWT middleware for authentication
2. Auth routes (login, register, profile)
3. Auth controllers with validation
4. Password hashing (bcrypt)

### Phase 4: Core API Routes
1. Tournament CRUD operations
2. Player CRUD operations  
3. Team CRUD operations
4. Basic error handling middleware

### Phase 5: Auction & Real-time Features
1. Auction state endpoints
2. Socket.IO setup and room management
3. Live bidding event handlers
4. Bid validation and atomic operations

### Phase 6: Final Configuration
1. Complete error handling
2. CORS setup for frontend integration
3. Environment validation
4. Development scripts

## Key Dependencies
- express: Web framework
- mongoose: MongoDB ODM
- socket.io: WebSocket real-time communication
- jsonwebtoken: JWT authentication
- bcrypt: Password hashing
- cors: Cross-origin resource sharing
- dotenv: Environment variables
- express-validator: Request validation
- express-rate-limit: Rate limiting

## API Endpoints to Implement

### Authentication
- POST /api/auth/login
- POST /api/auth/register  
- GET /api/auth/profile

### Tournaments
- GET /api/tournaments
- POST /api/tournaments
- PUT /api/tournaments/:id
- DELETE /api/tournaments/:id

### Players
- GET /api/players
- POST /api/players
- PUT /api/players/:id
- DELETE /api/players/:id

### Teams
- GET /api/teams
- GET /api/teams/:id
- POST /api/teams
- PUT /api/teams/:id
- DELETE /api/teams/:id

### Auction
- GET /api/auction/:tournamentId
- POST /api/auction/:tournamentId/bid

## Data Structures

### User
```javascript
{
  id: String,
  name: String,
  email: String,
  mobile: String,
  password: String,
  role: String,
  createdAt: Date,
  updatedAt: Date
}
```

### Tournament
```javascript
{
  id: String,
  name: String,
  status: String, // Active, Upcoming, Completed
  date: Date,
  teams: String, // "12 Teams"
  format: String, // "T20 League"
  createdAt: Date,
  updatedAt: Date
}
```

### Player
```javascript
{
  id: String,
  name: String,
  role: String, // Batsman, Bowler, All Rounder, Wicket Keeper
  style: String, // batting/bowling style
  keeper: Boolean,
  createdAt: Date,
  updatedAt: Date
}
```

### Team
```javascript
{
  id: String,
  name: String,
  short: String, // abbreviation
  players: Number, // current players count
  budget: String, // remaining budget in INR format
  maxPlayers: Number,
  totalBudget: Number,
  createdAt: Date,
  updatedAt: Date
}
```

### Bid
```javascript
{
  id: String,
  tournamentId: String,
  playerId: String,
  teamId: String,
  amount: Number,
  timestamp: Date,
  status: String // Active, Won, Outbid
}
```
